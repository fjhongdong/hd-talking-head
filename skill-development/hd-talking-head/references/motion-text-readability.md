# 动效文字的实际字号与可读性

适用于所有渠道的 A-roll 贴片和 B-roll。检查最终 1080×1920 画面，不用源 CSS、SVG 或 Remotion 字号冒充实测。原生 70px 字体经 0.5625 缩放后只有约39px，就是必须提前发现的问题。

正式合成会按 ShotRecipe 的 `render_window.safe_zone` 裁切组件；原生透明视频里完整可见的标题，仍可能在父级被裁掉。静态排版及文字目标须放入本次实际可见区域，例如当前 A-roll annotation 的顶部 64px 不显示；按最终合成帧核对，不能用未裁切的原生预览批准，也不能降低安全边距或改小实测字框来放行。

## 制作与自动检查

主控逐项列出本镜头真正承载信息的标题、正文、图中标签、数值和必要的界面文字。每个视觉组件都填写 `treatment.motion_readability`；没有关键文字时写具体原因，不能因为没有 OCR 结果就填“无文字”。尚未创作的 Barty / Bang 完整原生项按下节标明待制作，创作后再列实际文字。原生 before/after 等小字是否重要由本次语义决定，不设全局忽略词表。

- `production-defaults.json.motion_text` 是机器规则来源。最终画面主标题64px、说明文字48px是排版起点，已验收的64/56等清晰字号不主动缩小。保留字体层级与原生形状，不把所有字统一放大。
- `visual_canary` 检查实际选段；`visual_assets` 覆盖全部动效组件；`preview` 再检查字幕、小窗等叠加后的最终画面。正式封面偏移从 opening manifest 读取，不能写死。
- 按稳定阅读时窗的头、中、尾及约每秒抽取真实帧。每个稳定时窗至少0.5秒，不能在看到失败后缩成唯一好看的瞬间。短暂标记、持续缩放和打字效果要逐项看实际播放，不能只看组件中点或最好的一帧。
- 本地 macOS Vision OCR 提供每一行的像素框。主标题48px、说明文字36px的 OCR 行框高度是保守拦截线，不是 CSS 字号，也不代表所有字体的字高换算公式。源字号、嵌套缩放与最终行框要分清。
- 必须同时匹配目标文字、位置和时间。字幕区、人物小窗不能替代动效文字；同文不同位置需分别检查。多行文字拆成对应的文本跨度和目标，不能用整段合框高度通过。
- 一帧中明确的小字、或某个稳定帧的小字，不能由其他大字和好帧抵消。`fail` 先修媒体再重扫；未识别、低置信、缺帧、裁字或归属不明为 `needs_review`，不能算通过。

自动检查不代替实际可读性复查。宿主在本轮制作中主动查看全部动效的原尺寸稳定帧及实际播放，核对对比度、完整文字、遮挡和阅读时间；不等用户逐个指出。默认直接内部处理，不新增用户确认门。

文字旁有划线、章印、连线或同色装饰时，逐项核对其真实像素是否与字的笔画粘连；正常播放并检查进入、重叠及稳定关键帧，确认字形独立可辨。OCR 结果和字号通过不能证明线条没有被误当成字；粘连影响阅读时按原生公开能力修正，无法修正则停下分析。

文字随光标、对象或镜头快速移动时，播放最终实际合成的完整运动过程，并检查运动开始、最快段和停止附近的真实编码帧；留意文字重复、条纹、拖影和残影。稳定帧清楚或字号通过不能抵消运动期间的明显失真。发现问题先保留原产物和记录，分析原生输入与渲染采样，再通过所选渠道支持的原生输入调整运动、显隐或采样边界，保持已批准语义、跟随关系和可读时长；不修改第三方引擎。修正后在真实底图及最终字幕、头像合成中重新播放检查。

静态图片也是动效的输入。SVG、纸片和来源图先用真实字体栅格化并查看实际图片，再进入动画；字体名存在或 JSON 校验通过不能证明中文已显示。跨工具字体不能可靠解析时，使用当前已安装中文字库生成字形轮廓，并在同一矢量源保留对应文本的可访问标签，供文字来源引用。静态素材的主字也按最终位置和缩放检查，不能把空白、乱码或过小标签留给视频阶段。

## 冻结本次文字目标

在整表确认前，与现有 treatment 一起填写。每个目标绑定实际可见文字的原内容引用，不再建另一份文字正本。`region` 是最终合成画面内这一处文字的预期区域，不能用整张画布代替定位；`windows` 为当前段落局部秒数，覆盖完整稳定阅读阶段。

尚未创作的 Barty / Bang 完整原生组件使用 `{segment_id,component_id,pending_native:true}`，不以空 targets 或“无关键文字”冒充完成。确认时冻结语义、模板、时窗与用户指定文案；原生创作后，在现有 realization 内用实际源码引用、字区和稳定窗口替换待制作记录，并保留全部已确认文案。见[完整原生调用](native-motion-call-contract.md)。

必须在整表批准后才生成的素材，只有当前完整 `generation_plan` 已通过 `planned_generation_targets`、且尚无实际 brief 或完成媒体的选中目标，才能使用 `{segment_id,component_id,pending_generation:true}`。确认前列全 `visible_text` 中计划保留的准确文案；不虚构尚未生成的字形、文件或字区。已有 Wake 视频、固定 Adu brief 等必须补真实来源，不能借用待生成状态。

批准后仍走原生成队列与 realization：全部对应步骤须有真实完成和本 Job 的文件身份，再从实际绑定的原生产物或场景补文字目标、区域与稳定窗口。目标完整保留批准文案，不增删或改写；提示词、制作要求和语义任务不是实际字源。现有比较继续冻结语义全集、候选、所选渠道/模板、时窗、生成步骤/参数/次数及费用计划。仅允许这些明确待制作目标补齐派生文字；其他目标不变，正式审核冻结后不可直接覆盖。完成阶段一律拒绝 `pending_native` 或 `pending_generation`，实际字号、像素、动作和最终合成仍按原门验收。

生成镜头已明确批准由父级补固定标签时，使用[既有静态标签合成](generated-broll-skills.md#父级固定标签)，不要求生成模型重画文字。父级只编排真实透明 PNG、原生成视频及其准确窗口；可见文字引用实际用于 PNG 栅格化的输入，不能引用提示词。静态标签不能冒充跟随光标；视频中的目标移动而标签必须随动时，停在该镜头分析原生能力或具体修订，不能猜轨迹。

```json
{
  "motion_readability": [
    {
      "segment_id": "本次段落ID",
      "component_id": "本次组件ID",
      "targets": [
        {
          "target_id": "本期唯一的显示位置ID",
          "content_ref": {
            "path": "本Job内实际brief.json",
            "sha256": "该文件实际SHA256",
            "pointer": "/left/items/0",
            "value": "版本号"
          },
          "span": [0, 3],
          "role": "body",
          "region": {"x": 100, "y": 690, "width": 350, "height": 90},
          "windows": [{"start": 3.6, "end": 4.2}]
        }
      ]
    }
  ]
}
```

`role` 为 `title` 或 `body`。`span` 从引用字符串取显示片段；换行或分时展示时拆成多个目标，其跨度并集覆盖完整字段的有效文字。语义评审中明确引用的标题、标签、items、正文等可见文字同样必须覆盖，不能只测大标题漏掉小正文。引用必须命中真实 JSON 值，文件变化即失效。对于实际渲染的 HTML、TSX、JS 或 SVG 中的字面文本，可使用 `pointer: "text:起始字符位置:结束字符位置"`；位置按 UTF-8 解码后的 Unicode 字符计数，完整文件 SHA 和精确切片必须一致。绑定实际源码，不另造文字清单冒充来源。

没有关键文字的组件使用 `targets: []` 与 `no_critical_text_reason`，说明实际视觉主体为何不需要阅读文字。这个判断基于实际组件和当前语义，不用于回避需要阅读的界面或图表。

确认前尚未生成的图片可能实际带有原清单未逐字列出的文字。仅当宿主实看后确认文字没有改变该组件原确认语义，才在 treatment 的 `reviewed_generated_text` 逐条记录 `segment_id`、`component_id`、`text`、原确认组件完整 `brief` 作为 `source_quote`、该组件已批准生成图的 `source_image={path,sha256,bytes}`、`verdict:"pass"` 和审阅 `reason`。不得删除原确认文字；缺真实图、审阅或同组件原语义引用时停止。文字目标仍须给出真实区域与完整阅读窗。图内文字的 `content_ref` 可引用该已批准生成图片，使用 `pointer:"image-text"` 和实际文本；这只固定图片身份及人工判断，不能证明像素文字或语义正确，后续必须检查真实输出帧。HTML 等文本直接引用实际渲染源码。机器校验不代替宿主语义审阅，新增事实或无法确认的文字不放行。

已存在的目标随整张视觉清单冻结；完整原生待制作项按上述边界补齐后冻结。实际制作不得悄悄删目标、降角色或缩短窗口来跳过失败。排版修改按现有 revision 流程处理，编号不变。

## 自动失败后在本阶段修好

宿主先使用原生公开字号参数、自有静态字体覆盖、换行、扩大文本框或安全缩放；优先保留已确认文案和动画。不能为塞进旧容器继续缩小关键字，不能降低检查线，也不能把关键字改称装饰。需要改第三方内部动画或换来源时，遵守原有修订和授权边界，不自动增加收费生成。

修改后只重做受影响镜头，再完成必要的最终合成检查。已通过的小样不豁免其他镜头。当前错误没有改善时先重新定位原因，不盲目重复渲染。

`needs_review` 由宿主查看返回的真实帧，并在现有 `--review-json` 中填写 `motion_readability_resolutions`。每个未决采样点需要：

```json
{
  "target_id": "实际目标ID",
  "time": 3.85,
  "frame_sha256": "返回的实际帧摘要",
  "bbox": [110, 700, 180, 54],
  "text": "版本号",
  "reason": "原尺寸文字已核对完整，实际行框复核低置信识别",
  "unclipped": true,
  "unobstructed": true,
  "contrast_clear": true,
  "window_reviewed": true
}
```

实际文字框必须位于目标区域且达到当前行框基线；不能手填 CSS 字号或凭自由 QA note 放行。量框时只取当前字段的独立字形，排除相邻标题、正文、箭头、卡片及印章外框，不能把两行白字合成一个大框冒充单行字高。回填前核对四边完整落在冻结 region 内，并查看相邻文字是否实际重叠；越界或重叠先修版式，不裁小框、挪框或扩大目标区域来通过。计划内的划除、盖章按其语义与阅读时窗单独核看，不与背后的旧文字合框。缺采样先补实际帧，缺文字先修内容。OCR 或 Swift 不可用也返回待复核，不标机器通过。

正式阶段把当前报告存入原 `local-qa-<stage>-r*.json` 的 `motion_readability`，绑定当前计划、目标、媒体、检查规则及实际帧。交付入口复查相同门禁；直接改 approved 状态不能绕过未解决项。缓存只在这些身份与帧内容不变时复用，不改写历史 Job 的批准或媒体。
