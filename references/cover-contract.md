# 封面输出与质量合同

本合同只在 `cover_direction` 与 `cover` 阶段读取。它约束正式封面，不改变 B-roll 固定 9:16 的规则。标题的具体视觉层级、排列方式和画面关系另见[封面标题视觉样式合同](cover-title-style.md)。

## 输出比例

- 每个 Job 单独确认封面输出比例；比例是 `cover_direction` 的已批准字段，不从上一个 Job、子 Skill 或模板默认值继承。
- 支持用户明确选择 16:9、9:16、3:4 或其他 runner 已验证比例；只交付本 Job 已批准的比例，不顺带生成其他比例。
- 已认可的完整带字图、最终栅格、QA 和报告必须使用同一比例；仅选择本地排字时才生成同一比例的无字底图。用户修改比例时只修订 `cover_direction → cover`，不重新执行 content_analysis。

## 方向样板

- 人物参考图不得冒充封面方向主图；它只绑定人物身份。
- `cover_direction` 报审必须提供与已确认输出比例一致的构图样板，并明确标注“构图样板，非最终生成图”。样板直接展示标题安全区、人物区域、主题动作、外层概念和内层结论，不能只把这些信息写在说明文字里。
- 使用“AI 模型表层”叙事时，模型芯片、Transformer 层级块和神经网络节点必须直接可见；撕开后同时可见认知、行业经验、岗位上下文和工作流程。缺失任一层语义时不得报审。

## 人物与文字安全区

- 人物参考图只决定身份；动作、环境和道具必须服务当前主题。
- 文字必须处于已批准的安全区，不得遮挡额头、眼睛、鼻子、嘴、脸部轮廓，也不得切断承担叙事的手臂或双手。用户明确认可的图文穿插风格可让少量发丝与标题交叠，前提是人物身份和标题在正式尺寸成图中仍清楚；发丝交叠不等于允许遮挡五官。
- 本地排字路线由 runner 在发布前记录文字框、人物头脸保护区和交叠结果；交叠不为零时直接 QA FAIL。已认可的完整带字图不重新计算不存在的文字图层或伪造保护框，仍需在正式尺寸下人工检查文字、五官和叙事手部。
- 9:16 冲击型标题布局必须把人物保护区作为布局输入；检查最终像素框，而不是只检查文字锚点。标题、描边、阴影、旋转色块和装饰线的像素框均不得越界或与人物保护区相交。
- A-roll 人物保护框必须来自人物蒙版合成后的实际像素框；人物已经集成在生成底图中时，保护框必须在底图审核时标注为归一化坐标，并与底图、brief 一起哈希绑定。禁止仅用 `person_width_ratio` 或人物位于左/右来猜测保护区。
- 9:16 人物内置底图缺少已审核保护框时，必须在本地排版和发布前失败；A-roll 实际人物框与任一最终绘制框相交时同样失败。图文穿插候选的保护框至少覆盖完整五官、脸部轮廓和叙事手部；经本 Job 人工认可的非关键发丝可在保护框外参与穿插。测试必须包含高人物或抬手人物的真实相交反例，不能用同一套推测框循环自证。
- 当前布局若只验证过人物在右、标题在左，则人物在左的任务必须在调用生图/生视频服务前失败，不能静默套用未镜像的模板。

## 标题视觉重量

- 标题必须采用已批准的标题视觉样式；未指定或未实现时不得回退为普通居中两行字。
- `cover_direction` 必须明确主标题、完整信息层、关键词强调方式和标题与人物/道具的视线关系；选择黄色重点语路线时还须明确黄色重点语及可选的 `support_line`，这些字段缺失时停止报审。`support_line` 只能在 9:16 `style-07` 中使用，必须由用户认可的封面方向逐字批准。

- 9:16 知识类封面的标题有效宽度通常应为画布宽度的 80%–90%，不得沿用半屏窄栏导致字号被迫缩小。
- 长核心句优先使用 `content_analysis` 或封面人工审核明确批准的一到两行语义分组，不通过无限缩小字号塞入单行，也不允许渲染器按字符中点猜测断句。
- 已批准文案不得通过切片、字符上限或模板槽位被静默截断；显式分行去除空格后必须与完整已批准文案逐字一致。无法排版时在调用外部模型前失败并返回当前封面修订。
- 9:16 的 brief 校验器和渲染器必须共同支持一至两行；模板不支持分行覆盖或比例不是 9:16 时，在调用 provider 前返回明确的版式不匹配状态，不得忽略参数或先消耗生成额度再失败。
- 标题总区域应与人物和主道具形成视觉平衡；机器检查至少覆盖边界、纵向间距、字号下限和人物保护区。
- 选择黄色视觉锤路线时，不得同时叠加同方向文字阴影和面板投影，避免产生重影。
- 用户只调整封面标题时，仅修订 `cover`，不重新执行 `content_analysis` 或 `cover_direction`。完整带字图须重新生成并验收一张完整候选，不从已批准图反推无字底图，也不暗中本地改字；仅本地排字路线复用已绑定底图。
- 仅本地排字路线持久化并哈希绑定无文字 `cover-base.png`。该路线的标题-only 修订须验证旧 brief 除 `headline` 外完全一致，再复用底图；底图缺失、身份不匹配或其他方向字段变化时，在 provider 调用前失败。

## 叙事对比

- 封面使用撕开、揭开、打开或前后对比等隐喻时，外层概念与撕开后结论必须一眼可辨。
- “AI 模型表层”应使用可识别但不冒充真实产品的模型芯片、Transformer 层级块、神经网络节点或模型结构图；内层再显示认知、行业经验、岗位上下文和工作流程。两层不得只靠颜色区分。
- 新主题的完整候选可以由生图模型同时设计人物、场景与标题；这不是复用旧底图。中文必须逐字核对，乱码、糊字、无关文字、品牌标志或水印都不能报审。若本期明确选择无字底图加本地排字，底图不承担最终中文，准确标题由本地字体渲染。用户已批准带字的完整预览且逐字检查通过时，走下述原样复用路径，不得重新渲染标题。

## 已认可完整预览的原样复用

- 先确认用户认可的是这张完整成图，而非仅认可构图方向；记录原始 PNG 的 SHA-256，核对画面文字与 `cover_direction` 的标题、重点语和可选短语逐字一致。不一致先修订方向，不用旧文案重画，也不伪称预览已发布。
- 完整带字图路径向 `cover.prepare_cover` 传入 `approved_preview`、`approved_preview_sha256` 和实际生成提示词 `approved_preview_prompt`；不传 `generated_scene` 或 `approved_base`，也不生成 `cover-base.png`。只有明确选择本地排字/保留无字底图的路线才使用这些参数，无字底图与完整预览不能是同一文件。
- 最终比例图和 `cover-delivery-raster.png` 直接复制已认可 PNG 的原始字节。报告绑定源图路径、SHA-256、尺寸和发布模式；发布前重验源图身份。禁止再次生图、叠字、缩放或重新编码，也不制作缩略图。此规则只锁定本 Job 已认可的成图，不把本期人物、文案或背景硬编码到以后的视频。

## 报审门

- 新生成封面只发布已批准比例的正式成图；完整带字图的产物清单没有 `cover-base.png`。`cover-report.json` v3 的产物清单、哈希和素材回执不得包含封面缩略图。
- 报审前，在本次显式指定的项目根目录运行 `python3 -m edit.hd.tools.cli review-cover --job <Job绝对路径>`。此只读入口要求 full-v2 的 cover 为 ready_for_review 或 approved，重验正式成图、素材回执和当前工作流；不渲染、不写批准。失败退出 2 且 stdout 为空，停止报审，不回退到直接打开路径。
- 成功 JSON 的 `images` 仅含 `final`，其中包含 `base64`、`sha256`、`bytes`、`mime_type`、`path`；另有 `job_id`、`revision`。宿主解析 JSON 后，解码图片字节并复核 SHA-256、字节数和 PNG MIME，直接把这份完整封面快照作为附件/图片预览传给用户。`path`、`final_image` 仅用于定位来源，不能在校验后重新打开这些可变路径充当本次审核图。不要把 base64 大段打印成聊天文字；宿主若不能消费图片字节，则报告展示能力缺失，不假装已展示。
- 图片 JSON 可能超过工具默认输出上限。由宿主程序完整接收并解析，再交给图片通道；不要把截断的终端文本当作成功响应。若传输截断，调整接收上限或使用完整数据通道后重新运行只读报审，不重做封面生成。
- 宿主在 **cover 报审**中只展示完整封面快照，不另建缩略图、审核页面或确认门。
- 人工在正式尺寸下判断标题是否清楚、主题动作是否可辨、人物是否容易认出。尺寸、解码和来源哈希通过只证明技术一致，不证明美观或可读；OCR 识别成功也不能代替人工判断。完整带字图没有可复用的无字底图，改字须提交新的完整候选；本地排字路线才复用原有 `cover-base.png`。
- 检查比例、主体身份、头脸遮挡、手部结构、主题动作、外层/内层语义、中文准确性、标题视觉重量和边界安全区。
- 机器 QA 未通过时禁止进入 ready_for_review；保留失败证据，修订当前封面，不要求用户审核明显不合格图。
- 用户修改实际封面而未改变内容重点时，只失效 `cover`；修改比例、人物动作或核心隐喻时失效 `cover_direction → cover`，不重新执行 content_analysis。

## Code-generated alternative

`aroll-code-cover` 是 `cover` 阶段的精确 code-generated alternative，只在用户对当前封面 revision 明确选中时执行。它使用已批准 A-roll 人物与本地程序化排版，保留实际比例、人物框、字体和产物哈希。该 alternative 不改写 B-roll 的五类语义选择，也不允许 `visual_assets` 使用全代码替代已批准来源。
