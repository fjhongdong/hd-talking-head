# 9:16 视觉质量合同

本合同从 `visual_direction` 起生效，直到 delivery 完成。它约束视觉方案、真实渲染和交付验收；聊天里的临时印象不能替代已批准的 `visual-plan.json`。

## 画布、帧率与资源

- 只输出 9:16；成片和所有 B-roll 均为 1080×1920，不生成横屏或其他比例的替代版。
- 帧率继承当前已批准 `visual-plan.json` 和输入检查结果，不得擅自假设 30fps。所有时间、帧数、转场和末帧检查都以该帧率换算。
- 默认采用低内存执行：单进程，重型渲染并发为 1；分镜顺序渲染、及时释放浏览器与帧缓存，最后再合成。不得为了提速同时启动多个浏览器、Remotion 或 FFmpeg 重型进程。
- Agent 编排同样受限：默认只允许 1 个主 Agent 内联执行，不得为了提速新增子智能体；除非用户明确提出多 Agent，否则不改变此限制。

## A-roll 与字幕

- A-roll 保留实拍背景，不抠像、不替换背景，也不复制人物图层；只在原始画面上叠加动态视觉。
- 透明关键词贴片按语义切换多种样式、尺寸、位置与进入方式，并根据脸部、手势和字幕区域动态避让；不得长期固定在同一位置。
- 口播字幕一次最多两行，短句优先，避免一屏文字过密。重点词无背景底色，可放大、变色、描边或使用艺术字。
- “斜”和“错位”指整个重点艺术字的整体旋转、基线错位或字块错位，不是简单把字体改成斜体；不得挡脸。
- 字幕和贴片必须使用已批准的字体身份与文案。字号、字重、行距、整体旋转与错位参数进入 plan；缺少字体或文案身份漂移时不得渲染。

## B-roll 动态路由

- 每段先确定 `semantic_role`，再从 `local_material`、`official_material`、`code_generated`、`external_stock`、`ai_generated` 五类同级来源中选择 `none`、`single` 或 `hybrid`。不设来源优先级、不设来源配额、不做跨类替换。
- `official_material` 的图片和视频保留来源、发布者、URL 与本地记录；`code_generated` 保留依赖 Skill 调用记录；`external_stock` 保留许可记录；`ai_generated` 根据语义主动选择。
- 文案出现命名人物或 CEO、创始人、研究者等职务时，对应人物事实组件使用第一方官方视频或官方人物页图片；姓名、职务和来源必须在已批准可见文案或紧邻的官方标题卡中得到覆盖。
- AI B-roll 可生成无声视频，主口播音频必须连续。B-roll 普通字幕必须为 0；官方资料和 AI 视频可加透明关键词贴片，但只能补充重点，不能恢复整句字幕。

## 小头像

- 所有 B-roll 小头像统一尺寸、边框、阴影和安全区，位置可按版式变化但不得遮挡主信息。
- 裁切必须采用头肩裁切：头顶留少量空间，完整保留下巴、颈部和肩线；不能只剩头部，也不能裁到胸腰大面积空景。
- 从当前 A-roll 取同一时间轴画面；头像的主体比例与裁切锚点写入 plan，所有模板共用同一规范。
- 使用 [头肩头像合同](avatar-profile.md) 的 `composition.avatar`：共享 profile 绑定本 Job 的 A-roll SHA，位置及裁切轨迹按镜头冻结。缺少真实测量参数时，新 plan 和 renderer 拒绝执行，不回填固定旧坐标。测量值过门不等于真实人物检测或人工验收。
- 机械验收采用正式绑定阈值，并在每个 B-roll 的进入后、稳定段和退出前各抽一帧；任一代表帧不合格即扫描全部同类镜头。

## 代码海报系统

- 五类来源同级；只有在当前段落已经批准 `code_generated` 后，才执行模板内部顺序 `verified_third_party` → `verified_local_canonical` → `custom_fallback`。先过语义家族、容量、1080×1920 与对应来源的结构合同：第三方不接受 `structural`，本地 canonical 可使用已登记的自有结构，不能为了优先级牺牲文案贴合度。
- `verified_third_party` 必须带 `template_origin`、`verification_id`、源码/样片哈希和真实三帧证据。结构改造后立即降为 `custom_fallback` 并重新验收；第三方仓库声明、海报截图或横屏预览都不能代替验证器。
- 声明输入 schema 不等于实际参数绑定；源码或登记 adapter 必须真实消费输入。只有能独立完成竖屏整屏构图的入口才有整屏模板资格；组件可复用不等于 `verified_third_party`，组合多个组件补齐版式属于 `structural`。
- 不得为当前文案临时降低 `capacity`。候选模板容量不匹配或当前文案三态 QA 失败时，只在 `code_generated` 候选池内继续排名；不用虚构信息凑容量，不跨来源类别。
- 历史验证不豁免当前文案三态 QA：实际填充后重新检查进入完成、稳定和退出前画面的裁切、重叠、空占位、装饰依附、末帧跳动及头像安全区。
- 可验证整屏模板以当前注册表和验证器结果为准，不从旧家族或评审板数量推断。先按当前语义、信息容量、数值表达与当前内容 QA 筛选；仅在合格且质量相近的候选间，用未使用或较久未使用作为次要排序。不得为了用完一轮而强用不匹配模板，合适时允许重复。
- 每张海报默认 5–7 个有效信息单元：主标题、结论、证据/数字、关系或对比、来源/上下文、必要的视觉锚点。短句允许更少，但必须重新平衡构图。
- 不得用空卡片、空色块或无意义圆形凑密度；不得显示内部语义标签，如“主题”“结论”“关键值”“提问”“反馈”“对照”。这些词只允许作为生成器内部字段。
- 不得为了密度编造信息。信息不足时使用可验证的原文拆分、时间关系、因果关系、对比关系、官方来源和真实媒体，而不是虚构数字或结论。
- 装饰线、分割线、连接线必须明确依附标题、卡片边缘或两个被连接的信息单元；禁止在空白区独立悬空，不得穿过圆形、头像或文字。没有可验证依附对象时必须不渲染，不能用固定绝对坐标硬放。
- 主视觉区、说明区、头像区与底部结论区必须独立占位；所有文本使用内容测量与安全边距，禁止溢出、重叠、被裁半或出现大片无目的留白。
- 1080×1920 画布的 critical text 与头像使用 `soft-safe y=1700`，非 AI 主视觉和装饰使用 `hard-safe y=1800`。220px 是底部 soft 风险区，不是固定留白；底部 120px hard 风险区不得放关键文字。全屏媒体可以延伸到底，但不能承载被平台控件遮住才可读的关键信息。

## 动效与转场

- B-roll 切入时元素分层出现：背景/主容器、主视觉、标题、证据、装饰和头像依次进入，不得整屏同时淡入。
- 关系图类 B-roll 的进入顺序由语义方向决定：来源节点先出现，输入关系随后建立，汇聚节点只在输入完成后出现，输出关系完成后才展示结论，底部总结最后出现。ShotRecipe 分别绑定 `sources`、`hub`、`target` 和 `payoff`，结论或底部总结不得混入来源；字段已声明但为空表示该角色不渲染，不得从旧文案回填，连线仅在两端角色都存在时创建。实际来源少于模板容量时只画真实节点和连线，不生成空占位。SVG 路径使用渲染主时钟显式设置透明度和绘制进度；禁止仅凭 CSS 延迟声明判定时序正确。
- 退出采用自然的分层淡出或轻微回落，不使用突兀缩放、黑闪、白闪或整屏硬切。最后 8–12 帧必须保持连续运动并完成安全收束。
- 替换素材必须覆盖整个已批准语义区间，或覆盖 ShotRecipe 中明确批准的完整 phase；不得只覆盖动画镜头的前半段，再露出已经完成入场的静态末态。素材不足长时先重新计时或重做，禁止用冻结末帧、`repeatlast` 或临时缩短 overlay 补齐。
- 每个 B-roll 都要抽查最后 8–12 帧，逐帧比较画面几何、透明度和媒体时间；出现末帧跳动、媒体回卷、尺寸突变或重复最后一帧时不得交付。

## Preview 与 Delivery 验收

- 用 ffprobe 检查真实输出而不是配置声明：必须为 1080×1920、帧率与 plan 一致、包含视频流和原始口播音频、时长连续且可完整解码。
- 用逐词时间轴、timeline map 和代表剪点验证音画同步；A-roll、B-roll 小头像及任一剪点的最大音画误差为 2 帧，超过即失败。
- `qa-report.json` 必须记录画布、帧率、时长、音视频流、黑帧/冻结帧、末帧跳动、模板覆盖、头像裁切、文本越界和来源绑定结果。
- 官方视频至少抽查进入后、稳定段和退出前三帧，并用帧差或哈希确认真实运动；官方图片逐项核对人物身份、职务、来源标签和媒体哈希。二者不能只验收其中一种。
- 字幕与 B-roll 重叠数必须为 0；B-roll 期间只允许合同规定的透明关键词贴片。
- `delivery-manifest.json` 必须绑定 final、封面、字幕、edit plan、visual plan、asset manifest、QA、inspection、contact sheet 和关键帧证据的文件身份与哈希。
- 默认不加背景音乐；只有用户在当前 job 明确要求时才加入，并单独验证响度、ducking 和口播清晰度。
- Preview 联系表必须覆盖 A-roll、实际选中的五类 B-roll、长标题、底部结论、头像和每种实际使用模板；发现一处同类缺陷时检查所有相关镜头，不只修截图中的单帧。
