# 完整原生动效调用

按 [SKILL.md](../SKILL.md) 的唯一流程，分别为贴片与 B-roll 按语义定量，每项完整语义匹配一次、保留同用途全部已接通候选，在核实适配后先最大化渠道、再最大化模板，最后按时间覆盖必要补量。渠道、模板、选项和真实调用入口保持真实身份，不把内容变化算作新模板。

用户确认完整清单与费用后，将真实原稿、语义、素材、词锚、时窗、输出规格和安全区交给选中的完整原生 Skill；原生 Skill 自主设计并执行其完整流程及技术 QA。父级交接本句要表达的对象、关系或状态，不把候选标签的惯用表现提前写成必须动作。原生可省的文案槽保持可省，不为满足适配器而填入制作编号或示例内容。不改第三方源码，不用自写动画冒充原生输出。各来源的实际入口及参数以其对应接入文档为准。

`prepare_template_inputs` 和 `execute_native_skill` 从同一已确认 `proposal` 投影本项 `semantic_row`。用其中的原话、必要含义和画面任务准备本项。`proposal` 仍提供同渠道、同模板的整表语境。其他镜头只帮助本镜独立创作。原生 Skill 决定实际构图、动作与自身技术检查。

GBRO 的首尾帧准备也使用这份交接。`proposal` 指完整清单，`source_approval` 单独指确认回执。确认表展示 `required_content` 的含义和必须出现的词。渠道与模板仍在合格候选中联合最大化。当前 Job 确实缺少视频生成渠道时，才可用 `constraint_refs.requirement={source:"authorization",purpose:"video"}` 排除依赖该渠道的设计候选。局部返修仍沿用明确的改动范围和候选锁。

Wake 的 `semantic_goal` 直接取本组件唯一已确认语义行的 `semantic`，准备与首次执行采用同一依据；缺行或多行须先纠正。美术方案的 `focus` 不承担语义授权，也不要求给所有候选预写美术方案。图片、来源、词钟、用途及生成授权仍按现有原生合同核对。

独立镜头可以并行。真实记录输入、渠道、调用和输出；检查文件可用及必要尺寸、帧数、时长，合成后检查导出成功。母 Skill 不叠加代表样片、canary、逐镜 OCR／量框、多轮抽帧或语义、美观自动打分。执行失败先最小修本 Skill 并继续受影响分支，不阻断无关素材；请求结果未知先核实，不重发。成片后按用户反馈及原编号局部返修。新增来源的资格样片和美观评估只用于入库。

保留原生公开接口的真实规格。Lemo 中要求 30/60fps 的风格先按其原生帧率制作，再等时转换为母片 24fps，不通过修改第三方或变速来伪装兼容。Huashu 保留原生主题、材质、grammar 与场景流程；研究卡与不支持当前画布的路线不作为合格候选。Anidoodle 和 Sweety 继续使用各自完整原生工作流与真实透明入口，同一模板的贴片和 B-roll 用途不重复计算模板。

Garden 按已选原生风格为当前口播创作无声整屏画面。useAnimations 按实际图标语义与词锚调用官方动画数据，母片只编排透明层及可选短标签。两者的入口、原生边界及计数见 [Garden 与 useAnimations 调用](garden-and-useanimations.md)。

第三方动效交付无声画面，原声与已授权的音效由母片统一合成。使用公开的原生无声渲染接口，保留相关画面、素材、字幕与时间检查；未交付的原生混音和完整有声影片终检不作为画面交付条件。不得把无声素材完成说成有声影片验收通过。

适配器的原生 brief 含有 `authorization` 对象时，明确保留 `paid_generation:false`；只写各类调用次数为零不能替代这个字段。新增生成仍由母级按已确认清单执行，原生制作只消费本项已有或已完成生成的素材。

Sweety 风格保留完整原生视觉创作和 build，通过原生画面检查后调用 `video_renderer.render_chunk` 导出真实词窗对应的无声视频。它没有关闭整链字幕的公开参数，因此保留原生字幕和完整原话；父级从已绑定的完成结果核对真实词钟，仅在该窗口不再重复烧录。原声文件保持不变，原生构建所需的音频仅用于对齐和时钟，不进入动效媒体。历史完整影片的声音失败记录保留，不重签为通过。

清单确认前核实渠道和模板的真实调用路线、语义、词锚、源素材及生成授权，不要求先完成该镜的场景代码、工程、brief 文件或结果证明。确认后，输入齐备即交给原生 Skill 一次完成设计、工程、渲染和自身技术 QA；父级接收完整结果，不把一个原生任务拆成逐动作指挥。依赖尚未完成的镜头单独等待，已有但损坏的输入按错误处理。

执行兑现保留父级已确认的权限、原声、词锚、来源事实和真实素材身份，不能通过换 brief 扩大费用或替换来源。首次创建 brief 同样引用已确认的口播、词锚和本项素材；语音按准备动作给出的规范从剪后 A-roll 裁出。新增生成素材沿同一动效的既有授权和实际结果核对。原生内部选项、构图、场景代码及工程和结果路径仍由原生流程决定。

各适配器使用自身原生 brief。对固定路线，母 Skill 对照已确认的 `expression_basis.content` 核对实际消费的槽，例如 Riso 的 `data.say` 或 useAnimations 的 `labels`。对开放创作，通过 `task_source`、`creative_handoff` 或原生等价字段交接必要含义。继续在既有校验中核对口播、词钟、来源、权限与实际输入。视觉呈现沿用原生制作和整片人工终验。

固定槽核对实际生效的值、类型、索引和容量。Riso 的示意节点数不能证明团队人数，数字 `6` 也不能用 `60` 代替。HyperFrames 的模板与实际原生 route 一致。Sweety Web 有覆盖文字的参数时，核对参数合并后实际显示的词。

正式视觉阶段只派发当前已确认且输入齐备的原生任务，并绑定该项完整语义、选型依据和确切 brief。正式捕获、发布和完成产物复用均核对这份绑定。直接进入渲染的原生场景也绑定实际画面文件。即使口播与编号相同，新增必需内容也需要该项新的输入和结果，改工程目录名或说明文档无法代替画面变化。隔离资格样片沿用独立入口。执行可更新实际 `binding_snapshot`，候选评审保持与确认时一致。

汇合 `realization` 时，保留已确认的语义与选型 assignment，并将每项 beat 的 `binding_snapshot` 同步为该项实际完整 binding；不能继续沿用规划时尚无原生工程的占位绑定。透明贴片同时补齐每项 `overlay_alignment`，按实际原生路线和产物填写 `overlay_selection` 的动作与结构声明，沿用[透明贴片合同](aroll-overlay-contract.md)，不另做一轮选型或审批。固定 callout 的必要短标签在规划 `visible_text` 中声明，实际 DATA 与原生词锚记录保持同一标签；完整原生创作的内部文字仍由其流程决定。

原稿漏写但已实际说出的内容，可用于非证据型 A-roll 贴片：绑定本 Job 已批准剪后 A-roll 的真实身份、帧率和完整词钟，并在语义列表中引用本项时窗内的实际原话。此时 `content_item_ids` 可为空；不得填造原稿条目，B-roll 与事实、证据型画面仍使用原有来源要求。

词锚沿用原生格式：索引标签使用原生索引、原文和时间线校验；完整局部词表保留文字、数量、顺序与覆盖要求，时间允许 `1e-6` 秒的舍入误差。语音输入由父级现有入口裁出 mono、16kHz、PCM s16le WAV；源按批准时窗截取，候选完整解码后比较全部样本数量和内容，不截掉候选尾部再比对。

实际导入的父级来源素材只接受本项已确认引用或本项完成的生成结果。原生自行绘制、工程截图、代码、字体与正常中间产物继续按原生工作流创建，保留已有来源和工程证据。不能把所有 `assets/files` 图片都当父级来源，也不能仅因文件位于原生项目目录就认定原创；派生图保留其真实源关联。

需要区分新建媒体来源时，在已有 scene 的 `native_asset_origins` 中标识 `authored` 或 `derived`，绑定该媒体实际路径、哈希及已绑定工程源码的 `evidence` 描述符；`derived` 另列同项已批准的 `sources`。白板原生 PNG 也可引用同项已绑定工程中标为 `authored` 的原创 SVG，保留实际路径、哈希、字节数和工程证据；不接受跨项 SVG、派生链或循环引用。这只是来源元数据，不改变原生 brief，也不新增审批。复制改名的已知外来素材仍按原来源或内容哈希识别。

白板自绘 SVG 的路径使用 `M/L/H/V/C/Q/Z` 及其小写，将 `S/T` 平滑简写展开成显式曲线。冻结前用同版原生引擎的 `svg_to_strokes` 检查能否解析，并核对配准 PNG 的关键描边，尤其是继承自 `<g>` 的路线颜色和线宽。

## 贴片摆位

以本段实际剪后的 A-roll 为底图，给人脸及其在贴片时窗内的移动留出空间，同时避开字幕和编号。优先把位置交给原生布局；合成前对照贴片实际叠在真人上的效果，关注最靠近脸或展开范围最大的时刻。已有合适的预览可直接用，容易遮挡时仅补看该段的关键画面。

发现挡脸时，优先移到本段真实留白。支持母片静态垂直移位的透明图层用 `canvas_translation` 绑定原媒体并调整位置，复核有效内容完整留在画布内。原生字号、动作和词锚继续沿用。没有足够留白时，使用原生布局参数重新摆放，并只复核受影响片段。
