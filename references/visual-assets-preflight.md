# 视觉素材与执行前置条件

以 [Skill 唯一流程](../SKILL.md) 和[阶段执行入口](stage-runner.md)为准。先列贴片与 B-roll 语义清单、一次匹配候选、联合分配渠道和模板，再做时间覆盖校验。向用户确认完整清单及新增调用范围后制作；不要求先生成素材才能确认清单。

## 清单与授权

当前 `visual_direction` 的 artifacts 明确登记本轮 proposal 和实际用户授权。正式编译与 execution mapping 保留这两个引用，不从历史授权目录猜当前清单。发布前只有实际来源输入已准备的组件进入正式编译；尚需生成的项目保留明确的计划输入，不能伪造文件或完成记录。

每次新的上传动作与 `ready → submitting` 生成提交共用当前授权检查，核对实际请求、输入、渠道、模型及调用范围。返修清空当前视觉授权后，旧清单的未提交请求不能继续发出。新清单仍包含的相同请求沿用原 ID 和已上传素材；已提交或结果未知的请求只查询，已完成素材可按真实来源复用。封面等独立明确授权不强行挂到正文清单。

历史生成授权证明当时的来源，不等于当前可以再次付费。供应商动作已经签发后，保留原任务及结果记录，不假装能撤回，也不自动重发。

## 正式制作输入

进入 `visual_assets` 前重新加载 Job，确认 `visual_direction=completed`，并绑定本 Job 的正式计划、剪后 A-roll 和实际组件输入。保留来源、路径、文件摘要、画布、帧率、帧数与时钟检查。1080×1920、24fps 是最终画布；画面、字幕、人物圆窗和编号沿同一剪后时钟合成。

五类组件按实际来源校验，不由类别名称建立选型优先级：

- `local_material`：Job 内素材与已登记文件一致。
- `official_material`：官方来源和实际取得文件一致。
- `external_stock`：素材提供方、来源及使用依据与实际文件一致。
- `code_generated`：实际调用所选原生 Skill，保留渠道、模板、源版本、输入与真实输出记录。
- `ai_generated`：实际服务、模型、请求、生成任务和输出一致，不将本地整理结果冒充原生输出规格。

整屏 B-roll 的底层全屏组件使用 `layout_slot=full_frame` 和四边为 0 的组件 `safe_zone`，字幕与右下角人物圆窗由最终排版统一避让。原生 Skill 自身工作流与技术 QA 不变；母 Skill 不叠加 canary、逐镜三态抽帧、OCR、字框或父级静帧审批。

执行错误先定位并修复受影响分支。制作成功后一次合成并交片，美观、直观与听感由用户在成片后终验。反馈返修按原编号只更新受影响内容；已交付文件单独保留，新版不得继承旧版验收。
