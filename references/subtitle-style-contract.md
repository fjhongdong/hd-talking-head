# 全片字幕样式与上游调用

用户已确认的开发样片为 `skill-development/speech-test-output/full-source-20260924/video-use-test/edit/verify/aroll-standard-12-video-with-subtitles.mp4`。它验证的是 6.625 秒源区间 `107.600–114.225` 的画面、原声、Scribe 词级时码、TalkCraft 字幕组件和 A-roll 图形的合成效果；不是任意新视频的固定文案、时间轴，也不是正式 `full-v2` Job 产物。

## 能力归属和样式

- 字幕视觉来自已安装 `video-talkcraft` Skill 的 `template/motion-systems/Subtitles.tsx`，项目可读取的锁定上游源码位于 `edit/hd/integrations/talkcraft/upstream/template/motion-systems/Subtitles.tsx`。进入字幕阶段先读取上游 Skill 的 `SKILL.md`，核对组件源码身份，并实际调用该组件的 Remotion 渲染入口；本 Skill 只编排、传入本片文案与时码、核对产物，不另画一套近似样式。
- 已确认竖屏基线是深色半透明圆角字幕卡、白色粗体、关键词金色强调：A-roll `bottom=350`，B-roll 放在圆窗左侧的下方安全区（`left=80`、`bottom=260`、`width=640`），共同使用 `fontSize=48`；组件基线含 `padding: 14px 42px`、圆角 `14px`、`rgba(7,11,20,0.72)` 底板及 `fontWeight=600`。B-roll 长句做均衡换行，不能让字幕压住画面内的说明文字或右下圆窗；以最终 1080×1920 画面实测为准，不复制当前样片的文案或旧时码。
- 整句随词级时间窗口出现、结束，不加统一的 0.3 秒延长、逐字飞入或第二层字幕。强调词仅来自已批准精确关键词，在该词的语音时间点变金色并轻微上提、发光；不能使用不参与排版的横向缩放，否则标点或后续字会被压住。相邻强调至少间隔 2 秒，同一关键词至少间隔 15 秒才可再次强调，不设整片次数上限。预览前抽查带前后字及标点的实际动画峰值帧，确认字距、换行和安全区；统计各段高亮分布，若整片明显稀疏，先检查关键词命中和节流规则，不能让过度去重吞掉语义重点。
- 字幕计划发布前按内容章节列出“已批准重点词 → 真实转写命中 → 实际高亮”的逐项对账，并标出连续没有高亮的有声区间。开场、核心转折、案例数字和结论不能因内容地图漏项而整段无重点；遇到漏项须回到 `content_analysis` 补充与原稿一致且在原声中可精确命中的关键词，再按正式修订流程重跑，不从字幕阶段私自提炼或靠缩短冷却时间凑数量。不能以“有几十处高亮”替代逐个语义拍审查：用户反馈量级不对时，逐句盘点值得强调的动作、反差、数字与结论，对比实际命中与最长无强调区间，再重新提交有声样片。某句没有合适的精确重点词时保留普通字幕，不能硬亮无关字。

原生 B-roll 底部说明实片验收后，字幕的右下圆窗左侧基线改为 `bottom=228`，只向下避让 32px；`left=80 / width=640 / fontSize=48`、字体、背景卡和关键词动效均不变。正式字幕计划的 B-roll 验收框也须同步下移 32px（`y=1462 / height=230`），不扩大框尺寸或原安全区。上文 `bottom=260` 是此前样片基线，不再用于正式 B-roll；实际卡片须完整落在原安全区内，并抽查说明文字和字幕动画峰值不相交。

## 编排和验收

1. `subtitles_v2` 负责唯一正式字幕计划：读取已批准内容地图、Scribe 字级转写和剪后时间映射，为 A-roll 和有口播的 B-roll 都生成 cue。B-roll 字幕与 A-roll 使用同一轨、同一词时码和同一视觉样式，只改变位置避让圆窗；上游组件不能重新转写、改词或重分语义。
2. 正式字幕计划冻结上游组件、版本化适配器、输入和字幕计划 SHA-256 及 Remotion/React 版本；其源绑定关联本 Job 的视频、Scribe 转写和剪后区间。透明产物 SHA-256 进入既有材料回执和批准记录。真实上游进程必须成功退出，异常直接失败、不切回旧 renderer。每条 cue 的可见窗口与计划精确一致，SRT 与同一正文时钟对应。透明轨须实际解码并检查 alpha，不能只信容器标记。
3. `video-use` 在贴片和 B-roll 视觉层之后最后叠一次普通字幕。B-roll 有口播时字幕 alpha 必须非零，并避开圆窗与画面内标题；无口播的间隙须透明。不得让子 Skill 自带字幕与父级轨重复。TalkCraft 的 VP9 WebM 必须用 `libvpx-vp9` 解码 alpha；默认 VP9 解码器可能将透明处解成黑底。调用未显式选择该解码器的现成合成入口时，先以 `libvpx-vp9` 解码、无损转换为支持原生 alpha 的 QTRLE/ARGB MOV，再交给原入口叠加，不重写字幕样式或合成器。格式转换保留帧数、帧率和时码；最终画面要实际抽帧确认字幕外能看见底层画面，容器声明透明不算通过。合成后核对唯一口播音轨、进入/稳定/退出帧、字幕与声音及贴片的对应、无黑帧、1080×1920 和当前批准帧率。内部关键帧用于 QA，不制作缩略图交付物。

## 当前生产入口与验证边界

正式合成的画面和字幕输入都锁定为 1080×1920/24fps；FFmpeg 对这两路输入使用 `-reinit_filter 0`，避免资料段与口播段色彩元数据变化时重建滤镜、重置 `N` 和字幕时钟。仍检查真实完整帧数、全片时长和原声音画同步；不能放宽输出检查、用补尾画面掩盖截短，或重做已批准素材。Canary、正式生产与未变片段复用须使用同一实际媒体探针身份；相同检查函数不另起名称，真实适配器变更则按策略修订处理，不删除旧事务。

`subtitles_v2.py` 已通过 `edit/hd/tools/talkcraft_subtitles.py` 调用项目内 `edit/hd/integrations/talkcraft/subtitles/render.mjs`，使用批准的 TalkCraft 字幕组件版本化适配；不再调用旧 PIL 字幕视频编码。适配只负责传入真实词时码、精确窗口、整段关键词轻弹及透明输出，主题直接引用锁定上游。字幕使用 `schema_version=4`，cue schema 和原子发布流程不变；预览阶段拒绝缺失或变更的渲染器身份。旧字幕产物不能自动当作本样式使用。

仅从当前 A-roll 或 B-roll 段已批准的精确关键词中选择强调；相邻强调至少间隔 2 秒，同词再次强调至少间隔 15 秒。ASR token 可含多个汉字；关键词在 token 内时沿用该 token 的真实区间，不按字数均摊时间。读取已发布字幕时从已绑定的词记录和剪后映射重建输入，防止单独改动关键词时点。实际解码检查首尾透明、每条字幕的进入/退出边界及关键词动画峰值。

分句的8–14字是可读性目标，不能为了凑字数忽略原声中明确的停顿。分句器在相邻两条之间优先寻找约0.2秒以上的真实停顿（比较采用毫秒精度，不改源时码）；调整后两侧至少4字，仍须满足14字上限、实际盒宽和有效显示帧。已批准关键词与 `Intl.Segmenter` 识别的中文词语边界不得拆开。没有合格停顿时保留原分界，不增加高亮。实片须复核词组与语义；自动分词不能保证所有专有名词都正确，也不能把普通短语伪装成高亮关键词来绕过问题。

2026-09-26 的旧版同源开发测试实际调用此入口与 `video-use`：159 帧样片保持批准的圆形小窗、唯一原声音轨及既有画面；当时 B-roll 的 61 帧普通字幕 alpha 均为零。测试位置为 `skill-development/speech-test-output/full-source-20260924/video-use-test/edit/verify/talkcraft-subtitle-adapter-20260926/`。该结果只证明旧规则，不能当作当前全片字幕要求已通过；正式 Job 的新字幕轨和成片仍须单独验收。
