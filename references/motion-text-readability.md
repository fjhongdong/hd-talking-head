# 动效文字排版

制作以最终 1080×1920 画面中的有效尺寸为准。把裁切、透明留白和合成缩放算进版式，给字幕、人物小窗和编号留出空间。主标题 64px、说明文字 48px 可作排版起点，使用支持中文的清晰字体，并按原生设计保留文字层级。

首次排版时按实际文字换行、字形边界和动效最大尺寸设置卡片与内边距，再添加动画。内容放不下时增大内容区或重排，再缩减可省的文字或装饰；主体、文字和图形按最终可见尺寸整体落位。

可编辑 HTML 文字卡共用 [卡片样式](../assets/text-card-layout/card.css)，原生 Canvas 和手绘卡用实际字体测量文字后再画容器。HyperFrames 的网格、通知、聊天及界面文字，Sweety 的卡片、气泡和流程框，花叔的功能卡、截图卡、节点标签和数字卡，以及 Hypit 的聊天气泡在首次渲染时使用相应排版。卡片组的间距按原生布局随尺寸调整。

从零创作 HTML 或 React 镜头时，卡片内层用 `hd-text-card`，可编辑文字用 `hd-text-card-content`，底板高度基于内容，原生位移和缩放放在外层。Garden、Barty、Bang、BB Video、MG、CineCode、Lemo、OneTake、Video TalkCraft 和 Shotcraft 的制作入口会在首次渲染加载标记对应的共用样式。JavaScript 后建的 HTML 卡片在页面上加 `data-hd-text-cards`，React 跨文件卡片在入口加包含 `hd-text-card` 的注释。

首次构图时，将真实截图中的关键原文放进宽裕、无遮挡的主要阅读区。需要比较两处内容时，保留两处完整原文，优先同屏展示，例如一组请求和回复。画幅或原图条件受限时按口播依次放大，保留双方关系所需的上下文和真实出处，并留足稳定阅读时间。

书名和专名采用原文与正确标点，断行保持词语、专名和句意完整；画面文字须有真实来源，优先原稿，不能凭空添加事实。内部动效编号不填入原生标题、章节号或眉题；清单编号由母层统一显示，口播本身需要的章节或数值除外。核心主体与关系进入主要信息层，不让装饰字段取代正文。文字、图形与人物避免互相遮挡，阅读时间跟随实际口播时钟。图片生成文字与静态标签应如实区分来源，不能用提示词冒充实际输出。

选型时核对原生版式会突出哪些必填文字。大号字母、数字和缩写须有来源、符合本句语义，并让观众能直接读懂。必填栏只能用占位字符填充时，改选能把核心文案放在主位的模板。将「口播示例」等制作备注留在清单里，画面保留观众理解所需的事实限定与来源。若可能把假设数字读成实测数据，直接在文案里说明是假设。

强调型贴片按真人画面的实际背景定字色、字号与底色。背景复杂时可用有内边距的实底卡片，主字保持清楚的明暗对比，强调色只落在真正的关键词上。排好字的主次、对齐和留白，再让入场动作带出重点，并留足阅读时间。

用于解释画面的关键词通常一处用一两个短词。标签靠近它指的对象，随对应动作或结果出现，留出手机上能读清的时间。两侧各有动作时分别贴近两侧。优先用能解释本句的具体短词，例如「先做眼前事／其他先搁下」。画内标签避开正式字幕、真人脸和小窗，口播字幕继续按真实原声显示。

HyperFrames 的 `grid-card-assemble` 用于并列单行短标签时，卡片大小随图标和文字收紧。图标和文字组成一组居中摆放，四周保留均匀内边距。让文字和图标与卡片底色有明显反差，并在最终竖屏布局中完整显示，避开人物和字幕。需要调整时，用宿主静态样式处理尺寸、间距、字号和颜色，保留原生入场动作、词锚和透明输出。
