# 封面入场、A-roll 开场与可选配乐

设计开场、修改开头、用户要求封面进入视频或添加/调整 BGM 时加载。复用已批准内容地图、封面和视觉设计，不重新理解文案或重做已有人工确认。

## 正文先由 A-roll 引入

- 默认正文第一镜是实拍 A-roll：先让讲师引入话题，再在相应证据、人物或概念出现时切 B-roll。若本 Job 启用封面，顺序为“封面 → A-roll 引入 → B-roll”；未启用封面则直接 A-roll。只有用户明确批准其他开场结构才可例外。
- 不固定 A-roll 必须持续几秒。根据实际说话、内容地图的 hook 和证据区间确定第一处 B-roll 的入点，完整保留首句与口播动作，不用官方片头覆盖引入。
- 官方演讲视频的真实现场是证明“分享/演讲”的主阶段，不能以静态人物卡代替。持续时间和比例按该句语义确定；与 A-roll 开场规则共同记录在视觉计划，不重复确认已批准的关键词。
- 预览必须检查实际解码首帧、A-roll 引入区间以及第一处 B-roll 开始/稳定帧。播放器 poster、HTML 预览或孤立截图不能证明正式 MP4 的开场顺序。

## 批准与复用

- 每个新 Job 记录封面是否入场、BGM 是否开启；默认不加 BGM。用户本次明确要求优先于历史“不要配乐”的选择。
- 已批准封面绑定绝对路径、批准记录和 SHA-256。不能只按 `cover.png`、`final.mp4` 等文件名猜最新版本；多个 Job 同名资产尤其要核对。
- 只让用户审核新增的入场时长、转场与真实混音。清楚的组合选择就是该设计的批准，不要求再重复确认同一选择；它不等于完整成片最终批准。
- 配乐记录文件哈希、曲名、作者、来源 URL、可用许可记录、起播点及循环方式。先检查可用本地素材；外部生成或付费调用仍需当前 Job 授权。不得把 API 能调用等同于音乐已生成或已混入成片。

## 封面时间轴

- 仅当本 Job 已批准封面入场时，第一张实际解码的视频帧必须是已批准封面，不是播放器 poster 或封面附件。
- 记录纯封面帧数、过渡帧数与正文偏移。若先停留再与正文重叠淡入，正文偏移仅为停留时长，不再加一次重叠时长。
- 视频、口播、已烧录字幕与 B-roll 同步平移；导出的 SRT、章节和其他独立时间轴附件也要应用同一偏移。保留完整开头，不用覆盖或截短首句换取封面时间。
- 复用已批准动画和字体。允许重编码必要开头、在兼容关键帧拼接原视频；规格或解码验证不通过时使用受控重编码，不强行拼接。不能重新套模板导致正片与样片变化。
- 拼接以实际帧数和 PTS 为准，不用浮点秒数近似关键帧边界。比较片段真实色彩矩阵、range、像素格式与编码参数；需要转换时执行像素转换，不只改标签。新旧片段接缝检查亮度/色偏、连续帧及音频，避免开头修好却出现闪帧。

## 正式封面入场接口

当前兼容运行时通过 `edit.hd.tools.preview_v2.prepare_preview_v2(job, opening=...)` 执行，不额外创建媒体阶段。只有本 Job 的入场选择明确后才传入以下三项；帧数从用户批准的设计取得，不能复制示例作为批准：

```python
from edit.hd.tools import preview_v2, state

job = state.load_job(job_dir)
result = preview_v2.prepare_preview_v2(job, opening={
    "hold_frames": approved_hold_frames,
    "transition_frames": approved_transition_frames,
    "user_confirmation": current_user_confirmation,
})
```

- `hold_frames` 是正整数，`transition_frames` 是非负整数且小于正文总帧数；固定 24 fps。零过渡表示直接切入正文。纯封面区不播放口播原声，未启用 BGM 时静音；正文画面、原声和已烧录字幕同时从第 `hold_frames` 帧开始，重叠淡出不再次增加时长。
- 仅复用当前 `cover` 已登记且哈希一致的 `cover-delivery-raster.png`（1080×1920）及封面报告，未批准、尺寸不符或被替换时停止。运行时不重做封面，也不自动改变已批准的 A-roll / B-roll 顺序。
- `11-preview/opening-manifest.json` 固定封面、原 SRT、入场参数、正文偏移、总帧数、最终预览和偏移 SRT 身份。四个开场边界帧与常规抽帧一起进入 contact sheet 和 QA；通过编码后解码、帧数、SAR/DAR、原声轨数量和音画时长检查后，仅推进到 `ready_for_review`。
- `12-delivery/subtitles/subtitles.srt` 使用预览生成的最终时间轴，不能再次加偏移；原透明字幕轨放在 `plans/body-subtitles.webm`，与原视觉和字幕计划一起保留正文时钟。消费者通过 `opening-manifest.json.artifact_clocks` 识别，不把正文 WebM 当成与最终 MP4 零点对齐的字幕轨。当前不生成章节附件；未来新增此类附件也须明确时钟并适配偏移。
- 同一已发布预览再次调用时复用原字节，不重渲染；可以省略 `opening` 或传入完全相同的选项。修改入场参数或移除已启用的开场，先 `revise` 当前 `preview`，再调用；新预览和交付重新报审，上游已批准资产不重做。未发布预览省略 `opening` 时是正文直接开场，不隐式沿用其他 Job 的配置。
- 初始化时绑定真实运行时源码身份。旧环境缺少该接口或关键字参数时停止并报告兼容差异，不手改旧 Job 身份。发布回放、交付及最终确认继续走原有锁、产物登记与批准链；清单或偏移字幕缺失时不降级为正文版本。

## 正式 BGM 接口

通过同一个 `prepare_preview_v2(job, music=approved_music_options)` 调用；可与 `opening` 同时使用，不新增阶段。当前支持一首音乐覆盖完整最终时间轴，包括已批准封面区；不支持分镜重启、多曲串联或任意分段覆盖，不能伪造参数。未发布预览省略 `music` 表示无 BGM。

`approved_music_options` 必须完整包含：

- `material_id`、`material_sha256`：当前资料索引中的活动 audio；`license_material_id`、`license_sha256`：活动 documents 中的许可凭据。许可文件绑定不等于自动判断法律授权，用户须审核用途。
- `title`、`author`、`source`：非空曲名、作者和来源记录；`user_confirmation` 是本次实际选择原文，不是自动批准或示例文字。
- `selection`：`start_frame`、`end_frame`、`crossfade_frames`，都是 24 fps 整数帧；起点非负，交叉淡化大于零且小于选段一半。选段必须真实存在；不足目标长度时复用带交叉淡化的循环，不补静音。
- `mix`：显式 `voice_gain_db`（-30～12）、`music_gain_db`（-60～0）、`duck_threshold`（0.00097563～1）、`duck_ratio`（1～20）、`duck_attack_ms`（0.01～2000）、`duck_release_ms`（0.01～9000）、`fade_in_frames`、`fade_out_frames`（正整数且合计不超最终帧数）。数值是合法范围，不是建议全部使用极值；参数由本次试听设计确定。

原声和音乐输入须为双声道，拒绝隐式声道增益变化；需要转换时先明确取得转换参数并保留来源，不改批准字节。循环、淡化、ducking 使用 48 kHz 整数采样时钟。原声只延迟封面停留帧数一次；音乐是被压低的输入，原声仅作侧链控制。最终 MP4 只有一条混合音轨。

预览和交付均登记 `music-manifest.json`、`music-audit.m4a`（同次混音分出的 ducking 后音乐）、`music-license-source`（许可原字节，格式见索引原文件名）、`music-credits.txt`。清单绑定选曲、参数、原声及最终 MP4 SHA、最终编码响度和音乐审计响度。真峰值高于 0 dBTP、音乐综合响度低于 -60 LUFS 或非有限测量值会停止发布；这些是最低机器底线，不代表好听，试听应留出约 -1 dBTP 的编码余量。

同一 ready/approved 预览重试可省略参数或传完全相同选择，复用原字节；改曲、改参数、关闭音乐先 `revise preview`，然后重新报审预览和交付，不重做封面、关键词或正文。音乐/许可替换和撤回使用资料变更入口，完整 `background_music` 回执将影响定位到 preview 及 delivery。缺附件、哈希改变、资料退休或时钟不符时停止，不静默退回无音乐。发布中断沿用原事务恢复。

报审时提供实际 review.mp4 与音乐审计附件，明确要求检查人声是否清楚、音乐是否可闻、开头/结尾/循环是否自然；复用原 preview 人工门，不新增重复确认。自动测量不是人工核听，最终完成仍要求 delivery 的真实确认回执与完成审计。

## 重字修订必须验证真实音画

- “分—分享”“长—长期”等词内重复须删除真实音视频中的多余音节，不是改字幕；以唯一前后文定位到原片绝对时码，并保留完整正确词头。
- 从同一正式 EDL/renderer 导出剪点前后的局部核听片；对比源音轨和最终编码音轨，检查首句、尾句及全片其他可疑重字。转写会自动归一化口吃，不能用 ASR 没有重字作为删除成功的唯一证据。
- 改动口播时长须从最早受影响的 `speech_cleanup` / `edit_structure` 修订，更新后续时码、字幕和视觉绑定；只重做受影响范围。新的完整文件与 SHA-256 重新报审，不能把旧成片链接当成修复结果。

## 可听见、但不压住人声

- 先测人声综合响度与真峰值。过轻的人声先改善响度，再判断配乐与人声的比例；不能只把音乐不断减小。
- 以已批准试听的混音参数为起点，复核全片动态。可参考人声 -18 LUFS、音乐预降音量 -28 LUFS、最终真峰值约 -1 dBTP 以下；这些是调音起点，不是所有视频的固定规格。
- 配乐贯穿批准的覆盖区间，在说话时适当降低、停顿时平滑恢复。循环接缝做短交叉淡化，首尾做淡化；不在每个 B-roll 结束处重启或硬切音乐。
- 最终交付一条混合音轨，不能把音乐放成播放器未选择的第二条音轨。原口播内容与时序不变，不重新配音。

## 验证与交付

- 检查实际首帧、封面停留边界、淡入完成帧、音画偏移、帧数、SAR/DAR、音频时长及全片可解码性。
- 与已批准样片对比开头；对未改动视频，优先用移除时间偏移后的解码帧哈希证明画面一致，而不只检查文件存在。
- 测最终编码后音频的综合响度和真峰值；抽查开头、中间、结尾及循环接缝。保存 ducking 后音乐独立审计音轨或做混音差分，证明音乐实际非静音；仅有配置字段不算添加成功。
- 数值验证不等于听感验收。无法实际核听时如实说明，提供可播放成片供用户试听，不能声称“已听过、很好听”。
- 正式封面修改使用上述 `preview` 修订入口，记录输入与输出哈希、批准组合、偏移和 QA。只有运行时尚未支持的后期选项才单独记录研究或修订证据，不伪造参数、不手改 workflow，也不作为正式流程完成的证明。
- 报审最新完整文件与其 manifest，状态保持 `ready_for_review`。用户确认完整交付后才算完成；链接不能继续指向旧版或比较样片。
