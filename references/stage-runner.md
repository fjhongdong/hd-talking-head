# 阶段执行与续做

按 [SKILL.md](../SKILL.md) 的唯一流程和[阶段合同](stage-contracts.md)执行。使用包内 `run.py` 与已有实际入口，传入本 Job 真实素材、词时钟、所选渠道及经用户确认的完整清单和费用。原生工作流独立镜头可并行；制作完成后一次完整合成并交片。

保持真实状态：生产完成是 `completed`，用户人工终验接受才是 `accepted`。不得自动写 `approved` 或补造人工确认。封面实图、试听、样片、canary、逐镜 OCR／量框、额外抽帧或逐阶段质量审批均不是默认继续条件；原生 Skill 自身流程和技术 QA 不变。用户明确要求封面单独确认时，按[封面合同](cover-contract.md)执行独立展示和等待，不因文件已生成或正文已确认而跳过本期封面确认。

只检查文件可用、必要尺寸帧数时长与导出成功；保护原始素材。收费请求须处于已确认授权内，避免重复提交，结果未知时先核实。执行失败先定位并最小修本 Skill，再恢复受影响分支；无关素材不等待。审美、直观和听感问题在成片后接收用户反馈并按原编号局部返修，不重做无关镜头。历史 Job、成片与记录不迁移、不重签。

## 默认连续执行

```bash
python3.12 <skill-root>/run.py run_stage --job-context <workspace>/job-context.json --input-json <本次实际输入.json>
```

默认不传 `--stage`。入口在同次运行内继续已具备输入的机器阶段，直到交付或返回真实所缺输入、授权及工具动作。`input-json.stages` 可按阶段分别提供输入；没有新输入时省略 `--input-json`。单阶段排错、限定返修范围，或当前分支等待时推进已满足依赖的独立机器分支，可显式使用 `--stage`；不要把它作为正常制作的逐阶段交接方式。显式阶段仍检查状态、真实依赖、启动身份和授权，不能仅因未排在第一位就拒绝。例如 inspect 完成后可先处理口播，封面确认等待期间可整理剪后 A-roll；preview 仍须封面和正文全部齐备。用户要求的独立封面确认仍需等待真实确认；连续执行不等于跳过授权，也不等于自动重试外部请求。

一次响应可以同时包含生成、查询、模板输入准备及原生制作动作；宿主推进所有相互独立且已就绪的项，不因一项图片仍在生成而停住其他动效。每项只等待自己的真实依赖。已有输入损坏时先修本 Skill 或该输入，不能标成“尚未准备”以跳过；最终合成前核对全部实际产物及其授权对应关系。

顺序为全局授权检查、逐项只读检查、构造完整响应、最后签发生成／上传动作、直接返回。全局授权不成立时停止全部派发；单项坏输入或产物只阻断本项及依赖项，返回明确原因，同时保留其他可执行动作。多项签发时，后项失败不得吞掉先前已签发动作，也不得把已签发请求回滚后自动重发。原生检查、Job 重载、整段编译和可能失败的响应构造应放在签发之前。断电或输出中断造成结果不明时，沿现有查询和阻断流程处理。

续做响应的 `errors` 列表标明局部失败的 `segment_id`、`component_id` 和原因，生成步骤可另带 `step_id`；宿主继续处理同批其他有效 `actions`，先修复报错分支再继续该分支。存在错误、待执行动作或未完成依赖时，不进入最终编译或完成状态。全局授权错误仍整体停止，不作为局部错误吞掉。

队列状态查询不构建缺少未来输入的请求。GBRO 图片完成而首尾帧未准备时，返回原生准备动作；已有准备记录损坏时按真实错误处理。同镜头部分组件未准备时，仅计算已准备目标的实际布局，不补造兄弟绑定，也不提前整段编译。

同次运行内复用依赖未变化的源码、输入和原生媒体检查结果，结束后丢弃。源码条件包含本次选中渠道实际还原目录中的文件、目录和链接，不能只依赖压缩发布库存。首次仍完整核验，后续复查已有依赖库存；变化后重新检查。当前授权、所选路由与预期产物身份每次核对。

`operation_timing` 沿用本次阶段耗时，并记录输入检查、源码库存复查及复用的次数和耗时。不把用户等待、并行任务的重叠时长或后续 Skill 开发时间累加为渲染耗时；局部检查省时不等于整片提速，后者须以新任务从清单确认到交付的实际总时间判断。

## 查询、返修与终验

以下命令均通过包内入口执行，`<job-dir>` 取本 Job 的实际目录：

```bash
python3.12 <skill-root>/run.py job status --job <job-dir>
python3.12 <skill-root>/run.py job revise --job <job-dir> --stage visual_assets --reason <本次反馈> --artifact-scope <segment-id>
python3.12 <skill-root>/run.py run_stage --job-context <workspace>/job-context.json --review-json <本版真实用户反馈.json>
```

`--artifact-scope` 可重复，实际编号先解析到当前清单的 segment，不重编号。制作继续使用 `run_stage`；不提供通用人工 `approve`、手工 `ready/complete` 或第二套初始化入口。终验 JSON 标识本 Job、`stage=delivery`、用户看到的当前成片与交付 manifest，以及实际用户原话。默认入口和显式 `--stage delivery` 使用同一处理逻辑；旧版反馈拒绝，不静默丢弃。

交付身份来自当前阶段登记的 `12-delivery/delivery-manifest.json` 文件 SHA。稳定交片保存在 `delivered/<身份>/final.mp4`，回执位于 `manifests/delivery/<身份>/delivered.json` 与 `accepted.json`。以返回的 `delivery_file` 交片，后续返修不能覆盖它。全局工作流计数变化不使同一版验收失效；新交付身份必须重新终验。查询只读当前阶段身份，不扫描历史记录猜最新版，也不写回执。
